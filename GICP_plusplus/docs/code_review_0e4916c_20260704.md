# Code Review — commit `0e4916c` ("fix GLIM map resolution, yaw rate control, and snap-back")

Scope: full diff vs `9e7dbc0` (18 files, +1,442/−137) plus the one uncommitted
working-tree hunk in `projectDegenerateDelta`. Reviewed per `AGENTS.md`
guidance (checked its false-positive list; none of the findings below are on
it). Findings ordered by severity; **all fixes listed as APPLIED are in the
working tree** and verified structurally + against the run-12 log.

## Findings

### M1 — `verbose: false` silenced the SCAN DEBUG evidence the commit itself relies on  [FIXED]
`localization.yaml` ships `localization/debug/verbose_scan_log: true`
(evidence-first default) but also `localization/verbose: false`, and
`getParams()` clamps the node logger to WARN whenever `verbose_` is false —
which suppresses the INFO-level `SCAN DEBUG | status=ok/ok_partial` lines.
Result: the replay scorecard (`analyze_scan_debug_log.py`) would see only the
WARN-level rejected frames and report nonsense acceptance/streak/bucket stats.
(Run 12 worked only because its launch overrode `verbose`.)
**Fix applied:** the WARN clamp now requires `!verbose_ && !verbose_scan_log`;
when scan logging is requested with `verbose: false`, INFO stays enabled and a
one-shot note explains why. `verbose_` still gates the raw stderr debug prints.

### M2 — projected pose could bypass the finiteness guard  [FIXED]
`final_candidate` (possibly the degeneracy-projected pose) is assigned to
`current_pose`/`basePose` *before* the `gicp_valid` finiteness check, which
only guards the observer update. A pathological NaN from the projection
(hessian eigenvectors are guarded, but `AngleAxisd` on a borderline
non-orthonormal float→double product is not axiomatically safe) would poison
the next scan's prior. **Fix applied:** `final_candidate` adoption now also
requires `matrixFinite(degen.projected_pose)`; falls back to the raw
candidate otherwise.

### M3 — GLIM `CONCAT DEBUG` line passed a runtime string as the fmt format string  [FIXED]
`spdlog::info(oss.str())` treats the payload as a format string; any stray
`{}` (e.g. from a future field) throws `fmt::format_error` mid-mapping.
**Fix applied:** `spdlog::info("{}", oss.str())`.

### L1 — scorecard NaN-spelling portability  [FIXED]
`aux<i>_merge_dt_s` in the SCAN DEBUG line prints via `ostringstream`, which
renders NaN as `nan`, `-nan`, or `-nan(ind)` depending on platform; the
script's regex only accepted `nan`. **Fix applied:** regex tolerates all
three; parse verified unchanged on the run-12 log.

### L2 — `scan_time_span_s` staleness on early deskew returns  [FIXED]
The span was only reset on the `timestamps.empty()` path; deskew-off /
unsupported-sensor / empty-IMU-buffer returns republished the previous
frame's span. **Fix applied:** reset to −1 at `deskewPointcloud()` entry.

### L3 — uncommitted hunk endorsed (commit it)
The working-tree change `if (apply_eigen_projection && !hessian.allFinite())
return out;` is correct: a non-finite hessian must not silently disable the
yaw-only veto path, and the gate's reject condition
(`eigen_projection_wanted && !degen.valid`) still fires exactly as before
when the eigen projection was actually required.

### I1 — pre-existing (not this commit): snap twist rotation direction
`maybeSnapPoseToGT` maps GT twist into base with `R_gtbody_base * v`
(transpose of `T_base_gtbody`'s rotation). Expressing a gtbody-axes vector in
base axes should use `R_base_gtbody * v` — the current expression is the
inverse rotation. This predates the commit (the P2 rework kept the original
expression) and is a **no-op in the shipped config** (gt_body == base_frame,
identity extrinsic). Flag for whenever `gt_odom` is re-pointed at a
non-identity body frame; fix alongside a frames test, not blind.

### I2 — design notes verified sound (no action)
- **Locking**: the new `geo.mtx` acquisition in `callbackImu` (bias-at-
  buffering) never nests with `mtx_imu`; all other new lock uses are
  sequential, no order inversion. `state.b` writers (calibration paths) run
  on the same IMU-callback thread as the new reader.
- **P3 delta observer**: `observer_prior_pose_` is written only on accepted
  scans immediately before `updateState()` (same thread), never consumed
  stale (snap path doesn't call `updateState`). The 45°/100 m plausibility
  fallback is sane.
- **Bias single-application audit**: exactly one subtraction site
  (`callbackImu`); `propagateState` and the snap helper no longer subtract;
  calibration consumes raw values; `Kab/Kgb` online adaptation (disabled by
  default) would introduce only the same buffered-sample lag upstream DLIO
  has.
- **Gate ordering**: absolute fitness → ratio (wrong-basin, checked before
  partial update so a wrong basin is never partially applied) → degeneracy
  projection / fully-degenerate reject → jump on the pose actually applied.
  `ok_partial` counts as accepted everywhere (streak counter, baseline feed,
  `last_gicp_pose_`).
- **Warm-up seed direction of error**: `seedBaseline: 0.28` is the highest
  plausible floor; a too-high seed makes early gates *permissive* (safe),
  never over-rejecting. Correct failure direction.
- **Concat diagnostics**: reset at merge entry covers every early return;
  `-1` sentinel distinguishes concat-disabled; publisher vectors are sized
  after `getParams()` populates `aux_lidars_` (ordering verified).
- **Adapter gyro→twist**: cache and consumer both under `core_mutex_`;
  age check compares two ROS-mapped stamps (domain-consistent); the RTK
  republish copies the angular twist; `kMaxGyroAgeSec` as C++17 inline
  constexpr is fine.
- **gnss_global yaw gate**: `pose.covariance[35]` is rad² end-to-end
  (adapter converts deg²); interpolation takes the conservative max and
  propagates "unknown" correctly; unpopulated covariance preserves legacy
  behavior; only two `push_gnss_data` callers, both updated.
- **Configs**: all touched JSON parses (comment-stripped); YAML parses;
  dense-map profiles referenced by `config.json` exist; the three
  `merge_clouds` call sites all pass the new `frame_diag_log` argument.

## Round-2 review items (Codex P3 comments) — addressed

   `merge_clouds` without the new `frame_diag_log` argument, so the live node
   silently used the default `false` even with `config_sensors.json` enabling
   it. FIXED: `glim_ros.cpp` now passes `aux_concat.frame_diag_log`. (Mapping
   is operationally offline, but the live path is documented as matching the
   offline merge path — now it actually does.)
2. **CONCAT DEBUG lacked scan time span** — GICP publishes
   `scan_time_span_s`; GLIM's line didn't have the equivalent. FIXED: new

   `span=…s` to every CONCAT DEBUG line, computed on the merged cloud (or the
   primary on precondition bail-outs) and only when the diag is enabled
   (one O(N) pass, sub-ms at Luminar densities).
